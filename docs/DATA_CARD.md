# CareCall-Bench data card (v0.1)

## What it is
A synthetic hospital database and a set of simulated front-desk call tasks for evaluating
conversational AI agents. Built as a domain (`hospital_in`) for τ²-bench v2.0.0.

## Contents
| File | Description |
|---|---|
| `domains/hospital_in/data/db.json` | Hospital state: 12 departments, 40 doctors, 2,000 patients, ~7,000 OPD slots over three weeks, ~3,700 appointments, ~500 lab reports, 27 priced services, 5 insurance plans. Generated by `seed.py` from a fixed seed. |
| `domains/hospital_in/data/schema.sql` | SQLite schema of record; tests check the seed round-trips through it. |
| `domains/hospital_in/data/policy.md` | Front-desk policy given to the agent. |
| `domains/hospital_in/data/tasks.json` | 26 hand-written tasks (pilot and regression set, split `base`). |
| `domains/hospital_in/data/tasks_generated.json` | 240 generated tasks (120 English + 120 Hinglish twins), splits `generated`, `generated_b1`–`generated_b3`. Built by `taskgen.py`; do not edit by hand. |

## How it was made
- All records are generated by code from fixed seeds. Names are drawn from common Indian first
  names and surnames; dates, slots and reports are random within fixed calendars.
- Synthetic mobile numbers are `+91` followed by 10 digits **starting with 5**. Real Indian
  mobile numbers start with 6–9, so no synthetic number can belong to a real person. Tools and
  the schema reject any other format.
- Task constraints are chosen so exactly one database outcome is correct; each task's gold
  actions, a wrong move and "do nothing" are verified by tests.

## Personal data
None. No record corresponds to a real person. No real patient, clinician or hospital data was
used to build or calibrate the data.

## Intended use
Evaluating and comparing AI agents for front-desk calls: task completion, emergency escalation,
privacy, routing and code-mixed (Hinglish) robustness.

## Not intended for
Clinical decision-making, triage of real patients, or certifying any system as safe. The
red-flag list and routing guide are simplified and await clinician review.

## Known limitations
- Hinglish caller speech is produced by an LLM simulator and may not match real callers.
- No audio is distributed. The speech condition synthesises caller audio on the fly (Amazon
  Polly, Indian English and Hindi voices) and the hearing-test clips are regenerated with
  `simulator/hearing.py`; both voices are synthetic, not recordings of real callers.
- Scenario pools (red-flag types, panic scenarios, symptoms) are small; later batches reuse
  scenarios with different patients, doctors and days.
